Internal research note · Lexis capstone (SEP490) · 15 Nov 2026

Yes, Lexis runs on a harness. v2.0 makes it an agent harness.

A harness is the layer around a model: it feeds the model context, calls tools and services for it, keeps state, and controls what happens next. Service-Harness-Ts does all of that for Lexis, a voice tutor for English speaking practice. Lexis v1.0 is a workflow harness: code decides every step and the models fill in the words. Lexis v2.0 keeps that order and adds a bounded tutor agent loop, in which the model may call a tool, see the result and then answer.

01Definitions

This chapter answersWhat does "harness" mean, and why did the committee read it differently?

What the word means in the sources

The committee read "harness" as a wrapper around coding agents such as Claude Code or Codex. That is one family of harness, not the meaning of the word. The sources below define a harness by its role.

SourceHow it defines a harness
Claude Code docsClaude Code is the layer around the model that supplies tools and manages what the model sees. The docs name that layer directly: "This surrounding layer is what the term agentic harness refers to."
LangChain, The Anatomy of an Agent Harness (10 Mar 2026)Everything that is not the model itself: code, configuration and execution logic. It lists 11 components, from system prompts to memory and context compaction.
Harness Engineering, arXiv 2609.00006 (15 Jul 2026)The runtime that wraps a language model and turns it into an agent that can act. The paper separates it from an agentic framework (a library you import), an evaluation harness (wraps an agent to test it, the opposite direction) and an orchestrator (coordinates harnesses from above).
Anthropic, Building effective agentsDoes not define harness, but gives the split we need: in a workflow, code decides the path through LLM and tool calls; in an agent, the LLM directs its own process and tool use.

Three words we must not mix up

The team says the harness "orchestrates agents". That sentence is only safe if we say which meaning of agent we use.

WordMeaning in LexisExists today?
Agent versionA configuration record in Service-Agent: prompt template, model profile, tools and tool permissions. The Service-Agent README says it is the configuration registry for the harness and does not execute agents.Yes
AI roleA model call the harness makes at a fixed point in the flow: tutor reply, answer judge, evaluator, memory extractor, context compactor, plus STT, TTS and Laya.Yes
Autonomous agentAn LLM that picks tools in a loop and sees their results, as in Hermes, Claude Code and OpenClaw.In v2.0

So the accurate sentence is: the harness orchestrates AI roles and AI services, configured by agent versions. "Orchestrates agents" becomes true in the stronger sense once the tutor agent loop in section 7 exists.

01Định nghĩa

Từ "harness" nghĩa là gì theo các nguồn

Hội đồng hiểu "harness" là lớp bọc quanh các coding agent như Claude Code hay Codex. Đó là một họ harness, không phải nghĩa của từ này. Các nguồn dưới đây định nghĩa harness theo vai trò của nó.

NguồnCách nguồn đó định nghĩa harness
Tài liệu Claude CodeClaude Code là lớp bao quanh model, cấp tool và quản lý những gì model nhìn thấy. Tài liệu gọi đích danh lớp bao quanh này là "agentic harness".
LangChain, The Anatomy of an Agent Harness (10/3/2026)Mọi thứ không phải là bản thân model: code, cấu hình và logic thực thi. Bài liệt kê 11 thành phần, từ system prompt đến memory và nén context.
Harness Engineering, arXiv 2609.00006 (15/7/2026)Runtime bọc quanh một language model và biến nó thành agent có thể hành động. Bài tách harness khỏi agentic framework (thư viện để import), evaluation harness (bọc agent để kiểm thử, tức hướng ngược lại) và orchestrator (điều phối các harness từ bên trên).

Nhóm hay nói harness "điều phối các agent". Câu này chỉ an toàn khi nói rõ đang dùng nghĩa nào của từ agent.

02Reference designs

This chapter answersHow are the public harnesses designed?

How three public harnesses work

The team consulted these three designs. Each figure follows the official documentation, linked in its header; press Play or step through. Under each figure: what the docs say, and which idea shows up in Lexis code.

What the official docs say
  • Every entry point (CLI, gateway, cron, ACP, API server) hands the message to one AIAgent.
  • The turn runs in a fixed order: build or reuse the system prompt, compress if context is over 50%, make an interruptible model call, run tool calls and loop, then persist.
  • Tool calls pass through a registry with a dangerous-command check before they run.
  • The iteration budget defaults to 500 turns; a fallback model is tried on 429, 5xx or 401/403 errors.
Idea found in Lexis code
  • One application core behind three inbound adapters (WebSocket, REST, AMQP).
  • Layered prompt assembly: Lexis uses four layers.
  • Context compression in the background, and LLM failover with health tracking.
  • Persistent sessions and per-learner memory, in Postgres instead of SQLite.
What the official docs say
  • The loop has five steps: receive prompt, evaluate and respond, execute tools, repeat, return result. One round trip of tool calls is one turn.
  • max_turns and max_budget_usd cap the loop; without them it runs until Claude finishes.
  • Read-only tools may run in parallel; tools that change state run one after another.
  • Context accumulates across turns and is compacted automatically near the limit. Sessions are saved and can be resumed or forked.
Idea found in Lexis code
  • Budgets on every model call, and turn and duration limits per session.
  • Automatic compaction, and memory that survives across sessions.
  • A stream of typed events to the client (state, turn.complete, audio.done).
  • Taken in v2.0: the tool loop and the permission rules.
What the official docs say
  • One long-lived Gateway per host owns all messaging surfaces and exposes a typed WebSocket API (default 127.0.0.1:18789).
  • The agent loop is a serialized, per-session run that covers intake, context assembly, model inference, tool execution, streaming and persistence.
  • The agent RPC returns a runId at once; assistant, tool and lifecycle events then stream to the client.
Idea found in Lexis code
  • A WebSocket gateway as the single live control path for a session.
  • One turn at a time per session: the turn lock drops a second audio.end with session.busy.
  • Lifecycle events pushed to the client while the turn runs.

The two OpenClaw pages are long. Only the first part of each was read for this note: the overview, the components, and run-sequence steps 1 to 5.

02Kiến trúc tham chiếu

Chương này trả lờiCác harness công khai được thiết kế ra sao?

Ba harness công khai hoạt động thế nào

Nhóm đã tham khảo ba thiết kế này. Mỗi hình vẽ đi theo tài liệu chính thức, có link ở góc hình; bấm Chạy hoặc xem từng bước. Dưới mỗi hình là hai cột: tài liệu nói gì, và ý nào xuất hiện trong code Lexis.

Tài liệu chính thức nói gì
  • Mọi cổng vào (CLI, gateway, cron, ACP, API server) đều chuyển tin nhắn tới một AIAgent.
  • Một lượt chạy theo thứ tự cố định: ghép hoặc dùng lại system prompt, nén nếu context vượt 50%, gọi model (ngắt được), chạy tool call rồi lặp lại, cuối cùng lưu phiên.
  • Tool call đi qua registry và được kiểm tra lệnh nguy hiểm trước khi chạy.
  • Ngân sách vòng lặp mặc định là 500 lượt; model dự phòng được thử khi gặp lỗi 429, 5xx hoặc 401/403.
Ý có trong code Lexis
  • Một lõi application phía sau ba adapter vào (WebSocket, REST, AMQP).
  • Ghép prompt theo lớp: Lexis dùng bốn lớp.
  • Nén context ở nền, và LLM failover có theo dõi tình trạng endpoint.
  • Phiên được lưu bền và có memory theo từng học viên, dùng Postgres thay cho SQLite.
Tài liệu chính thức nói gì
  • Vòng lặp có năm bước: nhận prompt, đánh giá và trả lời, chạy tool, lặp lại, trả kết quả. Một vòng gọi tool là một turn.
  • max_turns và max_budget_usd giới hạn vòng lặp; không đặt thì vòng lặp chạy đến khi Claude xong việc.
  • Tool chỉ đọc có thể chạy song song; tool làm thay đổi trạng thái chạy lần lượt.
  • Context cộng dồn qua các turn và tự được nén khi gần đầy. Phiên được lưu, có thể resume hoặc fork.
Ý có trong code Lexis
  • Mỗi lệnh gọi model đều có ngân sách thời gian; mỗi buổi có giới hạn số lượt và thời lượng.
  • Tự nén context, và memory còn lại qua nhiều buổi.
  • Một dòng sự kiện có kiểu gửi về client (state, turn.complete, audio.done).
  • Có ở v2.0: vòng lặp tool và luật quyền.
Tài liệu chính thức nói gì
  • Mỗi máy có một Gateway chạy lâu dài, nắm mọi kênh nhắn tin và mở một WebSocket API có kiểu (mặc định 127.0.0.1:18789).
  • Vòng lặp agent là một lượt chạy tuần tự theo từng session, gồm nhận tin, ghép context, gọi model, chạy tool, stream và lưu.
  • RPC agent trả về runId ngay; sau đó sự kiện assistant, tool và lifecycle được stream về client.
Ý có trong code Lexis
  • Một WebSocket gateway là đường điều khiển trực tiếp duy nhất của một buổi.
  • Mỗi session chỉ chạy một lượt tại một thời điểm: khóa lượt trả session.busy cho audio.end thứ hai.
  • Sự kiện vòng đời được đẩy về client trong lúc lượt đang chạy.

Hai trang tài liệu OpenClaw rất dài. Bản ghi chú này chỉ đọc phần đầu của mỗi trang: phần tổng quan, các thành phần, và bước 1 đến 5 của trình tự chạy.

03Lexis v1.0

What the harness does in the speaking flow

Before the first turn, the harness loads everything the tutor needs, once, in initializeSession: practice authority and rubric from Service-Curriculum, the student profile from Service-Session, the mentor materials from Service-RAG (pinned for the whole session), and learner memory from its own database. The data belongs to those services; the harness fetches it. Nothing is reloaded during the session.

Where the data goes: in tutoring-loop classes the profile decides which grammar targets come first and how much help the tutor starts with, and the reply prompt carries the verified class preferences, the learner's words and the chosen move. In other classes the profile, learner memory and grounding go straight into the tutor prompt. Each load has its own deadline, so no single service holds up the start; a profile that takes longer than 3 s is filled in as soon as it arrives.

Service-Harness-Ts is a NestJS 11 service on Fastify with a hexagonal layout. Three classes do most of the work: SpeakingSessionService (session life cycle, about 4,400 lines), ExecuteWorkflowService (each turn and the grading, about 7,000 lines) and TutoringLoopService (what the tutor says, about 1,160 lines). The figure shows one speaking turn as the code on the dev branch runs it, with Laya switched on and the other switches as listed under the figure. Press Play, or step through it.

The order never changes. In tutoring-loop classes, code picks the tutor's move (ask, rephrase, hint, give a choice, model the answer) and the LLM writes the words for that move; in other classes the tutor model answers from the prompt the harness built. Either way the harness, not the model, decides what runs next. This is why the system is a workflow.

Grading never runs inside a speaking turn. When the session ends, one message goes to RabbitMQ and a consumer grades it in the background.

The harness keeps its own data small. It owns the schema harness in Postgres (16 tables), a few Redis keys, and nothing else. Turns and scores are stored by Service-Session; recordings go to Cloudflare R2.

03Lexis v1.0

Chương này trả lờiHarness của Lexis làm gì trong một buổi nói?

Harness làm gì trong luồng speaking

Trước lượt nói đầu tiên, harness tải một lần mọi thứ tutor cần, trong initializeSession: quyền làm bài và rubric từ Service-Curriculum, hồ sơ học viên từ Service-Session, tài liệu của mentor từ Service-RAG (ghim cho cả phiên), và learner memory từ database riêng của harness. Dữ liệu thuộc các service đó; harness gọi sang lấy về. Trong phiên không tải lại gì.

Dữ liệu đi về đâu: ở lớp bật tutoring loop, hồ sơ quyết định grammar target nào đi trước và tutor bắt đầu gợi ý ở mức nào, còn prompt sinh câu trả lời mang sở thích đã xác minh của lớp, câu học viên nói và nước đi đã chọn. Ở các lớp khác, hồ sơ, learner memory và grounding được đưa thẳng vào prompt của tutor. Mỗi lần tải có hạn thời gian riêng, nên không dịch vụ nào làm chậm lúc bắt đầu; hồ sơ nào về sau 3 s thì được điền vào ngay khi tới.

Service-Harness-Ts là một service NestJS 11 chạy trên Fastify, tổ chức theo kiểu hexagonal. Ba class làm phần lớn công việc: SpeakingSessionService (vòng đời buổi nói, khoảng 4.400 dòng), ExecuteWorkflowService (từng lượt nói và việc chấm điểm, khoảng 7.000 dòng) và TutoringLoopService (tutor nói gì, khoảng 1.160 dòng). Hình dưới là một lượt nói đúng như code trên nhánh dev chạy, với Laya đang bật và các công tắc khác như ghi ở dưới hình. Bấm Chạy, hoặc xem từng bước.

Thứ tự này không bao giờ đổi. Ở lớp bật tutoring loop, code chọn nước đi của tutor (hỏi, diễn đạt lại, gợi ý, cho lựa chọn, làm mẫu) và LLM viết lời cho nước đi đó; ở các lớp khác, model tutor trả lời dựa trên prompt mà harness đã ghép. Dù theo cách nào, harness chứ không phải model quyết định bước tiếp theo. Vì vậy hệ thống là workflow.

Việc chấm điểm không bao giờ chạy trong lượt nói. Khi phiên kết thúc, một message được đẩy vào RabbitMQ và một consumer chấm ở chế độ nền.

Harness giữ phần dữ liệu riêng ở mức tối thiểu. Nó sở hữu schema harness trong Postgres (16 bảng), vài key trong Redis, và không gì khác. Lượt nói và điểm do Service-Session lưu; file ghi âm nằm ở Cloudflare R2.

How the harness coordinates a class of 35

Inside the harness every learner has their own session, their own state and their own turn lock, so learners never wait for each other there. All sessions share the AI services on one Mac. The figure follows a class of 35 from the moment they connect until their sessions are graded.

  1. 1One seat per student

    Opening the WebSocket takes the student's seat in Redis with a 120 s lease that keeps being renewed, so the same student cannot hold two sessions at once. (redis-session-seat.service.ts)

  2. 2Each session keeps its own state

    Context window, audio buffer and timers live in the harness process, keyed by session id. Nothing is shared between learners, so sessions never slow each other inside the harness.

  3. 3One turn at a time per session

    A turn lock guards each session. If a turn is still running, one new audio.end may wait for it; any more get session.busy.

  4. 4Calls to AI-Voice

    STT and TTS are HTTP calls with client timeouts of 45 s and 30 s. AI-Voice runs one request of each kind at a time and holds a line of up to 16 more.

  5. 5Calls to the LLM

    All model calls go to one llama-server with 7 slots. The harness bounds each call: the answer judge has 1.2 s and a circuit breaker (3 failures pause it for 30 s), the tutor stream has a 30 s idle timeout, and the tutor can fail over to the next model candidate in the agent config.

  6. 6Recovery inside a turn

    If the lead-in phrase fails, the turn goes on without it. If speech to text or the tutor model fails, the learner is asked to try again and the session goes back to listening.

  7. 7Background work has its own line

    Rolling grading every 6 turns, summaries, context compaction and memory extraction share one line (BACKGROUND_LLM_ISOLATION_ENABLED=true): 1 running and 8 waiting, so they never take a tutor's place.

  8. 8Grading after the session

    The final grading job goes to RabbitMQ (session.evaluation.queue). The consumer takes 2 messages at a time; if RabbitMQ is down, the harness grades in process.

Harness điều phối một lớp 35 học viên thế nào

Trong harness, mỗi học viên có phiên riêng, state riêng và khóa lượt riêng, nên học viên không phải chờ nhau ở đó. Mọi phiên dùng chung các dịch vụ AI trên một máy Mac. Hình dưới theo chân một lớp 35 học viên từ lúc kết nối tới khi phiên của họ được chấm.

  1. 1Mỗi học viên một chỗ

    Khi mở WebSocket, học viên giữ chỗ của mình trên Redis với thời hạn 120 s được gia hạn liên tục, nên một học viên không thể giữ hai phiên cùng lúc. (redis-session-seat.service.ts)

  2. 2Mỗi phiên giữ state riêng

    Context window, audio buffer và các timer nằm trong process của harness, theo session id. Học viên không dùng chung gì, nên các phiên không làm chậm nhau trong harness.

  3. 3Mỗi phiên một lượt một lúc

    Mỗi phiên có một khóa lượt. Nếu một lượt vẫn đang chạy, một audio.end mới được chờ; các cái sau nhận session.busy.

  4. 4Gọi AI-Voice

    STT và TTS là lệnh gọi HTTP với timeout phía client 45 s và 30 s. AI-Voice chạy mỗi loại một request một lúc và giữ hàng chờ tối đa 16 request.

  5. 5Gọi LLM

    Mọi lệnh gọi model đi tới một llama-server có 7 slot. Harness giới hạn từng lệnh gọi: answer judge có 1,2 s và circuit breaker (lỗi 3 lần thì nghỉ 30 s), stream của tutor có timeout 30 s khi chờ token, và tutor có thể chuyển sang model dự phòng kế tiếp trong cấu hình agent.

  6. 6Phục hồi trong một lượt

    Nếu câu đệm lỗi, lượt nói vẫn tiếp tục. Nếu chuyển giọng nói thành chữ hoặc model tutor lỗi, học viên được mời nói lại và phiên quay về trạng thái nghe.

  7. 7Việc nền có hàng riêng

    Chấm cuốn chiếu mỗi 6 lượt, tóm tắt, nén context và trích memory dùng chung một hàng (BACKGROUND_LLM_ISOLATION_ENABLED=true): 1 chạy và 8 chờ, nên không bao giờ chiếm chỗ của tutor.

  8. 8Chấm điểm sau buổi học

    Job chấm cuối được đẩy vào RabbitMQ (session.evaluation.queue). Consumer nhận 2 message một lúc; nếu RabbitMQ không chạy, harness chấm ngay tại chỗ.

Mỗi tài nguyên dùng chung đều có giới hạn ghi trong code hoặc cấu hình, nên harness luôn biết một lệnh gọi được phép kéo dài bao lâu.

  1. Stage pipeline. Done when all current tests pass and eval:tutor equals the baseline.

Lexis v2.0 giữ mọi phần của v1.0 và cùng thứ tự cố định của các bước. Nó thêm một tutor agent loop có giới hạn với bốn tool, kiểm soát vào lớp cho cả lớp đông, checkpoint để resume, một trace xuyên suốt mọi stage, và một cổng chất lượng chạy hằng đêm.
