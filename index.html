Is our harness really a harness?

What Hermes Agent, Claude Code and OpenClaw publish about their harness design, where ESPP's Service-Harness-Ts matches it, and what to build so the name is fully earned.

Internal research note · ESPP capstone (SEP490) · 14 Nov 2026

Yes, it is a harness. It is not yet an agent harness.

A harness is the layer around a model: it feeds the model context, calls tools and services for it, keeps state, and controls what happens next. Service-Harness-Ts does all of that for a voice tutor. What it does not do yet is let the model choose an action and see the result in a loop. In the words Anthropic uses, ESPP today is a workflow, and the three reference systems are agents.

01Definitions

This chapter answersWhat does "harness" mean, and why did the committee read it differently?

What the word means in the sources

The committee read "harness" as a wrapper around coding agents such as Claude Code or Codex. That is one family of harness, not the meaning of the word. The sources below define a harness by its role.

SourceHow it defines a harness
Claude Code docsClaude Code is the layer around the model that supplies tools and manages what the model sees. The docs name that layer directly: "This surrounding layer is what the term agentic harness refers to."
LangChain, The Anatomy of an Agent Harness (10 Mar 2026)Everything that is not the model itself: code, configuration and execution logic. It lists 11 components, from system prompts to memory and context compaction.
Harness Engineering, arXiv 2609.00006 (15 Jul 2026)The runtime that wraps a language model and turns it into an agent that can act. The paper separates it from an agentic framework (a library you import), an evaluation harness (wraps an agent to test it, the opposite direction) and an orchestrator (coordinates harnesses from above).
Anthropic, Building effective agentsDoes not define harness, but gives the split we need: in a workflow, code decides the path through LLM and tool calls; in an agent, the LLM directs its own process and tool use.

Three words we must not mix up

The team says the harness "orchestrates agents". That sentence is only safe if we say which meaning of agent we use.

WordMeaning in ESPPExists today?
Agent versionA configuration record in Service-Agent: prompt template, model profile, tools and tool permissions. The Service-Agent README says it is the configuration registry for the harness and does not execute agents.Yes
AI roleA model call the harness makes at a fixed point in the flow: tutor reply, answer judge, evaluator, memory extractor, context compactor, plus STT, TTS and Laya.Yes
Autonomous agentAn LLM that picks tools in a loop and sees their results, as in Hermes, Claude Code and OpenClaw.Not yet

So the accurate sentence is: the harness orchestrates AI roles and AI services, configured by agent versions. "Orchestrates agents" becomes true in the stronger sense once the tutor agent loop in section 7 exists.

01Định nghĩa

Chương này trả lờiTừ "harness" nghĩa là gì, và vì sao hội đồng hiểu khác?

Từ "harness" nghĩa là gì theo các nguồn

Hội đồng hiểu "harness" là lớp bọc quanh các coding agent như Claude Code hay Codex. Đó là một họ harness, không phải nghĩa của từ này. Các nguồn dưới đây định nghĩa harness theo vai trò của nó.

NguồnCách nguồn đó định nghĩa harness
Tài liệu Claude CodeClaude Code là lớp bao quanh model, cấp tool và quản lý những gì model nhìn thấy. Tài liệu gọi đích danh lớp bao quanh này là "agentic harness".
LangChain, The Anatomy of an Agent Harness (10/3/2026)Mọi thứ không phải là bản thân model: code, cấu hình và logic thực thi. Bài liệt kê 11 thành phần, từ system prompt đến memory và nén context.
Harness Engineering, arXiv 2609.00006 (15/7/2026)Runtime bọc quanh một language model và biến nó thành agent có thể hành động. Bài tách harness khỏi agentic framework (thư viện để import), evaluation harness (bọc agent để kiểm thử, tức hướng ngược lại) và orchestrator (điều phối các harness từ bên trên).
Anthropic, Building effective agentsKhông định nghĩa harness, nhưng đưa ra cách phân loại nhóm cần: trong workflow, code quyết định đường đi qua các lệnh gọi LLM và tool; trong agent, LLM tự điều khiển quy trình và việc dùng tool.

Ba từ không được dùng lẫn

Nhóm hay nói harness "điều phối các agent". Câu này chỉ an toàn khi nói rõ đang dùng nghĩa nào của từ agent.

TừNghĩa trong ESPPHiện đã có?
Agent versionMột bản cấu hình trong Service-Agent: prompt template, model profile, tool và quyền dùng tool. README của Service-Agent ghi rõ nó là nơi lưu cấu hình cho harness và không thực thi agent.Có
AI roleMột lệnh gọi model mà harness thực hiện ở một điểm cố định trong luồng: tutor trả lời, answer judge, evaluator, memory extractor, context compactor, cùng với STT, TTS và Laya.Có
Agent tự chủMột LLM tự chọn tool trong vòng lặp và xem kết quả, như ở Hermes, Claude Code và OpenClaw.Chưa

Vì vậy câu nói chính xác là: harness điều phối các AI role và dịch vụ AI, được cấu hình bằng agent version. Câu "điều phối các agent" theo nghĩa mạnh sẽ đúng khi có tutor agent loop ở mục 7.

02Reference designs

This chapter answersHow are the public harnesses designed?

How three public harnesses work

The team consulted these three designs. Each figure follows the official documentation, linked in its header; press Play or step through. Under each figure: what the docs say, and which idea shows up in ESPP code.

What the official docs say
  • Every entry point (CLI, gateway, cron, ACP, API server) hands the message to one AIAgent.
  • The turn runs in a fixed order: build or reuse the system prompt, compress if context is over 50%, make an interruptible model call, run tool calls and loop, then persist.
  • Tool calls pass through a registry with a dangerous-command check before they run.
  • The iteration budget defaults to 500 turns; a fallback model is tried on 429, 5xx or 401/403 errors.
Idea found in ESPP code
  • One application core behind three inbound adapters (WebSocket, REST, AMQP).
  • Layered prompt assembly: ESPP uses four layers.
  • Context compression in the background, and LLM failover with health tracking.
  • Persistent sessions and per-learner memory, in Postgres instead of SQLite.
What the official docs say
  • The loop has five steps: receive prompt, evaluate and respond, execute tools, repeat, return result. One round trip of tool calls is one turn.
  • max_turns and max_budget_usd cap the loop; without them it runs until Claude finishes.
  • Read-only tools may run in parallel; tools that change state run one after another.
  • Context accumulates across turns and is compacted automatically near the limit. Sessions are saved and can be resumed or forked.
Idea found in ESPP code
  • Budgets on every model call, and turn and duration limits per session.
  • Automatic compaction, and memory that survives across sessions.
  • A stream of typed events to the client (state, turn.complete, audio.done).
  • Not taken yet: the tool loop itself, hooks, and permission rules.
What the official docs say
  • One long-lived Gateway per host owns all messaging surfaces and exposes a typed WebSocket API (default 127.0.0.1:18789).
  • The agent loop is a serialized, per-session run that covers intake, context assembly, model inference, tool execution, streaming and persistence.
  • The agent RPC returns a runId at once; assistant, tool and lifecycle events then stream to the client.
Idea found in ESPP code
  • A WebSocket gateway as the single live control path for a session.
  • One turn at a time per session: the turn lock drops a second audio.end with session.busy.
  • Lifecycle events pushed to the client while the turn runs.

The two OpenClaw pages are long. Only the first part of each was read for this note: the overview, the components, and run-sequence steps 1 to 5.

02Kiến trúc tham chiếu

Chương này trả lờiCác harness công khai được thiết kế ra sao?

Ba harness công khai hoạt động thế nào

Nhóm đã tham khảo ba thiết kế này. Mỗi hình vẽ đi theo tài liệu chính thức, có link ở góc hình; bấm Chạy hoặc xem từng bước. Dưới mỗi hình là hai cột: tài liệu nói gì, và ý nào xuất hiện trong code ESPP.

Tài liệu chính thức nói gì
  • Mọi cổng vào (CLI, gateway, cron, ACP, API server) đều chuyển tin nhắn tới một AIAgent.
  • Một lượt chạy theo thứ tự cố định: ghép hoặc dùng lại system prompt, nén nếu context vượt 50%, gọi model (ngắt được), chạy tool call rồi lặp lại, cuối cùng lưu phiên.
  • Tool call đi qua registry và được kiểm tra lệnh nguy hiểm trước khi chạy.
  • Ngân sách vòng lặp mặc định là 500 lượt; model dự phòng được thử khi gặp lỗi 429, 5xx hoặc 401/403.
Ý có trong code ESPP
  • Một lõi application phía sau ba adapter vào (WebSocket, REST, AMQP).
  • Ghép prompt theo lớp: ESPP dùng bốn lớp.
  • Nén context ở nền, và LLM failover có theo dõi tình trạng endpoint.
  • Phiên được lưu bền và có memory theo từng học viên, dùng Postgres thay cho SQLite.
Tài liệu chính thức nói gì
  • Vòng lặp có năm bước: nhận prompt, đánh giá và trả lời, chạy tool, lặp lại, trả kết quả. Một vòng gọi tool là một turn.
  • max_turns và max_budget_usd giới hạn vòng lặp; không đặt thì vòng lặp chạy đến khi Claude xong việc.
  • Tool chỉ đọc có thể chạy song song; tool làm thay đổi trạng thái chạy lần lượt.
  • Context cộng dồn qua các turn và tự được nén khi gần đầy. Phiên được lưu, có thể resume hoặc fork.
Ý có trong code ESPP
  • Mỗi lệnh gọi model đều có ngân sách thời gian; mỗi buổi có giới hạn số lượt và thời lượng.
  • Tự nén context, và memory còn lại qua nhiều buổi.
  • Một dòng sự kiện có kiểu gửi về client (state, turn.complete, audio.done).
  • Chưa lấy: chính vòng lặp tool, hook, và luật quyền.
Tài liệu chính thức nói gì
  • Mỗi máy có một Gateway chạy lâu dài, nắm mọi kênh nhắn tin và mở một WebSocket API có kiểu (mặc định 127.0.0.1:18789).
  • Vòng lặp agent là một lượt chạy tuần tự theo từng session, gồm nhận tin, ghép context, gọi model, chạy tool, stream và lưu.
  • RPC agent trả về runId ngay; sau đó sự kiện assistant, tool và lifecycle được stream về client.
Ý có trong code ESPP
  • Một WebSocket gateway là đường điều khiển trực tiếp duy nhất của một buổi.
  • Mỗi session chỉ chạy một lượt tại một thời điểm: khóa lượt trả session.busy cho audio.end thứ hai.
  • Sự kiện vòng đời được đẩy về client trong lúc lượt đang chạy.

Hai trang tài liệu OpenClaw rất dài. Bản ghi chú này chỉ đọc phần đầu của mỗi trang: phần tổng quan, các thành phần, và bước 1 đến 5 của trình tự chạy.

03ESPP today

This chapter answersWhat does our harness do during a speaking session?

What the harness does in the speaking flow

Service-Harness-Ts is a NestJS 11 service on Fastify with a hexagonal layout. Three classes do most of the work: SpeakingSessionService (session life cycle, about 4,400 lines), ExecuteWorkflowService (each turn and the grading, about 7,000 lines) and TutoringLoopService (what the tutor says, about 1,160 lines). The figure shows one speaking turn as the code runs it today.

The order never changes. Code picks the tutor's move (ask, rephrase, hint, give a choice, model the answer); the LLM writes the words for that move. This is why the system is a workflow.

The committee asked this directly. The harness owns the schema harness in Postgres (16 tables), a few Redis keys, and nothing else. Turns and scores are stored by Service-Session; recordings go to Cloudflare R2.

03ESPP hiện tại

Chương này trả lờiHarness của ESPP đang làm gì trong một buổi nói?

Harness làm gì trong luồng speaking

Service-Harness-Ts là một service NestJS 11 chạy trên Fastify, tổ chức theo kiểu hexagonal. Ba class làm phần lớn công việc: SpeakingSessionService (vòng đời buổi nói, khoảng 4.400 dòng), ExecuteWorkflowService (từng lượt nói và việc chấm điểm, khoảng 7.000 dòng) và TutoringLoopService (tutor nói gì, khoảng 1.160 dòng). Hình dưới là một lượt nói đúng như code đang chạy.

Thứ tự này không bao giờ đổi. Code chọn nước đi của tutor (hỏi, diễn đạt lại, gợi ý, cho lựa chọn, làm mẫu); LLM viết lời cho nước đi đó. Vì vậy hệ thống là workflow.

Hội đồng đã hỏi thẳng câu này. Harness sở hữu schema harness trong Postgres (16 bảng), vài key trong Redis, và không gì khác. Lượt nói và điểm do Service-Session lưu; file ghi âm nằm ở Cloudflare R2.

04Orchestration

This chapter answersHow does the harness coordinate the models and AI services?

How the harness coordinates models and services

The harness calls each AI role at a fixed point, with its own model, time budget and fallback. No role calls another role; the harness is always in the middle.

AI roleTechnologyWhen the harness calls itBudget and fallback in code
Speech to textService-AI-Voice, Parakeet-MLX (parakeet-tdt-0.6b-v2), Silero VAD, smart-turnAfter audio.endEmpty transcript is retried; the turn is handed back to listening if there is no audio
Answer judgeLLM through LangChain ChatOpenAI; default qwen2.5:1.5bBefore the tutoring policy decides1,200 ms timeout
Tutor replyLLM chosen by the agent version in Service-Agent; OpenAI-compatible local serverOnce per turn, streamedCandidate list with priority; failover to the next endpoint; first-sentence budget 1,200 ms in companion mode
Grounding and packsService-RAG (LightRAG, pgvector)Session start and before each promptOwn timeouts per request, for example 3,000 ms for the exemplar pack
Text to speechService-AI-Voice profiles: LuxTTS, Kokoro ONNX, Gemini TTS, OpenRouter TTSPer sentence, as the reply streamsOne request per sentence; time is recorded per stage
EvaluatorLLM, default qwen2.5:1.5b, temperature 0.1; LanguageTool detectorAfter the session, from the queue45,000 ms per call; two attempts; failure is recorded, no score is invented
Memory extractor, context compactorLLM, backgroundOff the live pathBackground admission: 1 running, queue of 8; extractor budget 25,000 ms
Laya decision modelLocal classifier served by laya-serveAfter the tutor has spoken (shadow)300 ms deadline, 2 at a time, confidence floor 0.8; never changes the reply

Model names are the defaults in src/config/llm.config.ts. The deployed stack overrides them by environment; the team's October notes show the router serving qwen2.5:3b-instruct-q4_K_M. The .env files were not read for this note.

08Committee Q&A

This chapter answersWhat will the committee ask, and how do we answer honestly?

Questions we should expect, and honest answers

1What does your harness store?

Run records and traces, every model call, evaluation records, and learner memory, in its own Postgres schema of 16 tables; live seat and pause state in Redis. Turns and scores are stored by Service-Session.

2Is it a wrapper around Claude Code or Codex?

No. It does not use them. Claude Code is a harness for coding; ours is a harness for a voice tutor, written in NestJS around local models. The Claude Code docs define a harness as the layer around the model that provides tools and manages context, and that is the layer we built.

3Where is the agent?

Today there are agent versions (configuration) and AI roles (fixed model calls). There is no autonomous agent yet. The tutor agent loop in section 7 is the planned step.

4Why not let the LLM decide everything?

A lesson needs a reply within a few seconds, from a small local model, and the teaching move must be safe for the learner's level. Anthropic's guidance is to prefer a workflow when the task is well defined. We keep rules for the move and plan a small, bounded loop for the wording.

5How is this more than an API gateway?

A gateway forwards requests. The harness owns the conversation: it assembles the prompt, keeps and compacts context, remembers the learner, enforces time budgets, fails over between models, checks the output and grades the session.

08Hỏi đáp hội đồng

Chương này trả lờiHội đồng có thể hỏi gì, và trả lời trung thực ra sao?

Các câu hỏi nên chờ sẵn, và câu trả lời trung thực

1Harness của các em lưu cái gì?

Bản ghi run và trace, từng lệnh gọi model, bản ghi chấm điểm và learner memory, trong một schema Postgres riêng gồm 16 bảng; trạng thái chỗ ngồi và tạm dừng của buổi đang chạy nằm ở Redis. Lượt nói và điểm do Service-Session lưu.

2Nó có phải lớp bọc quanh Claude Code hay Codex không?

Không. Harness của nhóm không dùng hai công cụ đó. Claude Code là harness cho việc lập trình; của nhóm là harness cho một AI tutor bằng giọng nói, viết bằng NestJS quanh các model local. Tài liệu Claude Code định nghĩa harness là lớp bao quanh model, cấp tool và quản lý context, và đó chính là lớp mà nhóm đã xây.

3Agent nằm ở đâu?

Hiện có agent version (cấu hình) và AI role (lệnh gọi model cố định). Chưa có agent tự chủ. Tutor agent loop ở mục 7 là bước đã lên kế hoạch.

4Sao không để LLM quyết định hết?

Một buổi học cần câu trả lời trong vài giây, từ một model local nhỏ, và nước đi sư phạm phải an toàn với trình độ học viên. Anthropic khuyên ưu tiên workflow khi bài toán đã được định nghĩa rõ. Nhóm giữ luật cho nước đi và dự định thêm một vòng lặp nhỏ, có giới hạn, cho phần lời.

5Nó hơn một API gateway ở chỗ nào?

Gateway chỉ chuyển tiếp request. Harness nắm cả cuộc hội thoại: nó ghép prompt, giữ và nén context, nhớ học viên, giữ ngân sách thời gian, failover giữa các model, kiểm tra đầu ra và chấm điểm buổi học.
